# Agent Monitor для Windows

Виджет на рабочем столе и иконка в трее: лимиты **Claude Code** и **Codex** (5 часов и неделя) и список сессий, которые **ждут вас**.

Порт [paveler/agent-monitor](https://github.com/paveler/agent-monitor) (macOS, MIT) на Windows. Сделан на Tauri 2: ядро на Rust, интерфейс на HTML/CSS/JS.

## Что умеет

- **Лимиты.** Кольца по 5-часовому и недельному окну, время до сброса. Кольцо желтеет с 75% и краснеет с 90%.
- **Ждут вас.** Сверху красным: агент просит подтвердить команду, задал вопрос или принёс план. Ниже: агент закончил ход. Клик по строке открывает эту сессию.
- **Трей.** Иконка показывает число ждущих сессий: красная, если кто-то заблокирован. Левый клик поднимает виджет поверх окон, повторный возвращает на рабочий стол. Правый клик открывает меню.
- **Без настройки.** Использует логины, которые уже есть у Claude Code и Codex CLI.

## Настройки (правый клик по иконке в трее)

- **Показывать.** Claude и Codex, только Claude или только Codex: фильтр действует на кольца, список задач и счётчик в трее. Там же отключаются целиком блок лимитов или блок задач.
- **Один агент — крупный вид.** Когда выбран только Claude или только Codex, лимиты занимают всю ширину: крупный процент, полоса с белой отметкой темпа (сколько времени окна уже прошло), прогноз («в таком темпе хватит на…») и график 5-часового лимита за сутки. Замеры для графика копятся в `history.json` раз в 5 минут и хранятся 7 дней.
- **Вид.** Лимиты: авто (кольца для двух агентов, крупно для одного), кольца, полоски (как маленький виджет оригинала) или крупно с графиком. Размер: узкий (240), обычный (380) или широкий (560 пикселей). Тема: как в Windows, тёмная или светлая.
- **Раскладка задач.** Список в две строки, компактно в одну строку или карточки (две в ряд, в широком виджете три, в узком одна). Сколько задач показывать: 3, 6, 12 или все.

Настройки и положение окна хранятся в `%LOCALAPPDATA%\AgentMonitor\settings.json`.

## Сборка и запуск

Нужны Node.js, Rust (MSVC) и WebView2 (в Windows 11 уже есть).

```powershell
npm install
```

```powershell
npm run build
```

Готовый файл: `src-tauri\target\release\agent-monitor.exe`. Установщик (NSIS) собирает `npm run installer`.

После запуска:

1. Перетащите виджет в удобное место за любое пустое поле.
2. Нажмите в виджете «Подключить Claude Code» и/или «Подключить Codex» (или в трее: «Интеграции»). Уже открытые сессии надо перезапустить. Codex попросит подтвердить хуки: `/hooks` в CLI или Settings → Hooks.
3. Включите в трее «Запускать при входе в Windows».

## Как устроено

| Агент  | Откуда логин                      | Откуда лимиты |
|--------|-----------------------------------|---------------|
| Claude | `~/.claude/.credentials.json`     | `api.anthropic.com/api/oauth/usage` |
| Codex  | `~/.codex/auth.json`              | `chatgpt.com/backend-api/wham/usage`, запасной вариант: последнее событие `rate_limits` в `~/.codex/sessions` |

Хуки вызывают тот же бинарник: `agent-monitor.exe --hook claude|codex`. Он читает событие из stdin, обновляет файл сессии в `%LOCALAPPDATA%\AgentMonitor\sessions\`, ничего не печатает и всегда завершается с кодом 0, поэтому на поведение агента не влияет. Хуки ссылаются на копию бинарника в `%LOCALAPPDATA%\AgentMonitor\bin\`, так что приложение можно перемещать и пересобирать.

| Событие | Состояние |
|---|---|
| `PermissionRequest`, `Notification: permission_prompt` | Нужно подтверждение |
| `AskUserQuestion`, `elicitation_dialog` | Вопрос к вам |
| `ExitPlanMode` | План на ревью |
| `Stop` (в фоне ничего не работает) | Ваш ход |
| `UserPromptSubmit`, `PostToolUse` | работает (скрыто) |
| `SessionEnd` или процесс агента завершился | удалено |

Переход к сессии: приложения Claude и Codex открываются на нужной сессии через их deep links (`claude://`, `codex://`). Для остальных (Windows Terminal, VS Code) на передний план выходит окно, в котором работает агент; выбрать вкладку терминала Windows не позволяет.

## Важно знать

- **Оба адреса для лимитов недокументированы** и могут измениться без предупреждения.
- **Токен Claude.** CLI обновляет токен, только пока запущен. Если он истёк, Agent Monitor обновляет его так же, как CLI, и записывает обратно в `.credentials.json` (атомарно, с проверкой и откатом при сбое).
- **Только системный маршрут.** Запросы идут через прокси, который включён в Windows (его выставляет VPN-клиент), а если прокси нет — обычным соединением, которое VPN заворачивает целиком. Запасного пути нет: переменные окружения (`HTTPS_PROXY`) и блок `env` в `~/.claude/settings.json` не читаются, в обход VPN приложение не ходит. Выбранный маршрут пишется в `app.log`. PAC-скрипты (автонастройка прокси) не поддерживаются.
- **Командная строка.** `agent-monitor.exe --connect claude|codex` и `--disconnect claude|codex` делают то же, что пункты «Интеграции».
- **Правка конфигов.** «Подключить» добавляет хуки в `~/.claude/settings.json` или `~/.codex/hooks.json`. Чужие хуки и порядок ключей сохраняются, рядом кладётся бэкап `*.agentmonitor-backup`. «Отключить» убирает только хуки Agent Monitor.
- **Win+D** сворачивает и виджет. Левый клик по иконке в трее возвращает его.
- Журнал ошибок: `%LOCALAPPDATA%\AgentMonitor\app.log`. Трассировка хуков включается переменной `AGENT_MONITOR_DEBUG=1`.
